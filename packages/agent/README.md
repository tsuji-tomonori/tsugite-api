# 継手APIのチャット

ログイン後に最初に開く「チャット」で公開APIを検索し、使い方ガイドに沿って操作を案内します。質問に合う候補がないときは、回答欄の「この質問を運営に送信」を押すと元の質問が運営に届き、受付番号が表示されます。管理者は問い合わせ一覧で回答し、依頼者は同じ画面で確認できます。問い合わせ本文と回答は Aurora DSQL に保存します。

## 質問から回答まで

1. FastAPI の Lambda が利用者を認証し、バックエンドのジョブワーカー（`app.core.chat_jobs.handler`）を非同期に起動します。DynamoDB の従量課金テーブルに一時結果を置き、ブラウザーは受付番号で状態を確認します。利用者本人にだけ結果を返し、表示時に商品の公開範囲とガイドの対象ロールを再確認します。
2. Ruri が商品検索、ガイド、対象外の日本語例文と質問を比較します。検索クエリのモデルは許可された検索先と短い検索語を JSON で返します。元の質問と生成した検索語の関連を確かめ、元の質問でも検索します。
3. 商品は既存の語句・業務概念の検索にモデルの類似度検索を加え、質問の対象を登録情報で確かめた候補の順位を統合して最大3件表示します。モデルが生成した検索語で初めて見つかった候補には、元の質問との意味の一致も必要です。埋め込みの対象は1回の検索で先頭240件までです。ガイドも語句と意味で検索し、生成モデルが出典と操作手順を選びます。表示する手順と商品情報はポータルに登録された原文を使います。
4. 問い合わせの送信は利用者のボタン操作で行います。送信内容はモデルに渡らず、チャットから実行できるモデル操作は読み取り専用の検索と回答箇所の選択です。

## HTTPと検索の責務

API Gatewayから呼び出すHTTPルートは、1エンドポイントのサービスもFastAPIで定義します。チャットのHTTP入口はバックエンドの `POST /api/chat` と `GET /api/chat` です。ワーカーはLambdaイベント、判定・検索語生成・回答箇所選択の各モデルはワーカーからの同期Lambda呼び出しで動きます。

`packages/agent` はモデルの判定で商品・ガイドの読み取りツールを選び、元の質問と検索語から得た候補の根拠を評価します。モデル停止時には、明示された検索意図と登録済み資料の一致を使います。バックエンドは利用者の認証、閲覧可能な検索資料の取得、ジョブの受付・保存、結果取得時の公開範囲の再確認、画面に返す回答の組み立てを担当します。

商品の全文検索は、Aurora DSQLから取得した閲覧可能な商品の名前・概要・所有者・OpenAPIの説明や操作名を `app.core.catalog_rank` がPython上で照合して順位付けします。ガイドはポータルに同梱した記事を検索します。チャットはそれぞれの候補にモデルの埋め込みによる順位を加えます。

## 開発時の検証

`task test:agent` はチャットの判断・検索の単体テストと、SQLiteを使って質問の受付から回答の取得までを確認するチャットAPI結合テストを実行します。モデルの構成と検証手順は[推論モデル](../model/README.md)に記載しています。
