# PRの説明欄を書く

1. [PRテンプレート](../../../.github/pull_request_template.md)を開き、見出しと順序をそのまま本文に使う。各欄の記入ガイドを、このPRで確認した事実に置き換える。
2. ベースブランチとの差分と関連要件を確認する。先行PRの変更を含む場合は、このPRでレビューする範囲と取り込み順を書く。
3. 検証結果はローカル実行とCIを区別する。各結果を記載する前に出力またはジョブを確認する。未実施なら理由を、CI待ちなら対象ジョブを書く。
4. GitHubの画面、CLI、APIのどこから作成しても同じ本文を使う。CLIでは記入済みのMarkdownを `gh pr create --body-file` または `gh pr edit --body-file` に渡す。
5. 公開前に、全欄に内容があり、記入ガイドが残っていないことを確認する。既存PRを更新するときは、レビューに使われているリンクや判断理由を対応する欄に残し、古くなった差分・検証結果を更新する。
6. [要件と証跡の更新手順](../../../docs/requirements/README.md#機能変更と証跡を更新する)に従い、変更した機能ごとに要件・理由・受入テストを照合する。マージ後は対応するデプロイと証跡保存を確認する。
