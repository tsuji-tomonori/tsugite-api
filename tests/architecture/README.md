# プロジェクト全体のアーキテクチャ規則

`task test:architecture` で以下の規則と検査器自身の回帰テストを実行する。PRのCIでは `task test` が同じディレクトリを収集する。

| 対象 | 検査する規則 |
| --- | --- |
| バックエンド | DBとエージェントのジョブ受付を利用できる。画面、CDK、モデル推論の実装を直接インポートしない。公開カタログ操作のIDとルーターを維持する。 |
| データベース | ORM、接続、マイグレーションをHTTP・画面・CDKから独立させる。 |
| フロント | ブラウザー用コードがバックエンド、DB、CDK、エージェント、モデルに直接依存しない。 |
| フロントの画面分割 | `portal_pages/` の公開モジュールは `SCREENS` に担当する画面を定義する。起動処理・共通レイアウトでのURL別描画分岐、共通ナビゲーションでのURL別の非同期取得、個別画面の直接インポート、画面から起動処理・共通レイアウトへの依存を検出する。`_` で始まる補助モジュールと、同じ機能の一覧・詳細の併記は許可する。 |
| インフラ | CDKの起動スクリプトと構成定義が、配備するアプリやモデルのモジュールを読み込まない。リソース設定値・タグ・費用・スナップショットは各CDK単体テストで確認する。 |
| エージェント | 実装は `packages/agent/src/agent/` に置く。バックエンドとDBを利用できる。検索処理からはガイド本文とガイド検索を再利用できる。推論実装と画面描画を直接インポートしない。 |
| モデル | 推論コードをAPI、ジョブ処理、画面、DB、CDKから独立させる。モデル取得元をコミットで固定し、重みにSHA-256を持たせる。 |
| 開発ツール・テスト | 実行用コードから開発ツールやテストをインポートしない。開発ツールは各層の実装を参照でき、テスト用コードの読み込みを検出する。各層の単体テスト、E2E、このディレクトリのテストに、条件と期待結果を日本語1行で書く。 |
| 文書 | ルート、各パッケージ、要件、生成設計書などのMarkdownに、日本語を含む表題を書く。要件は索引生成器と同じ規則でファイル名・要件文・4節・共通語彙を検査する。API・DBの和名は定義元のコメントから取得し、設計情報の外部辞書や正規表現でのコード解析を検出する。 |

Pythonの依存規則は `dependencies.py` に定義する。新しいパッケージを加えたら所属層と許可する依存を定義し、`test_rule_checks.py` に適合例と違反例を追加する。エラーには対象ファイル、行番号、依存先が表示される。

規則を変えたときは `task test:mutation -- --layer architecture` をローカルで実行する。検査器の条件を一時コピーで変更し、その変更を回帰テストで検出できるか確認する。
