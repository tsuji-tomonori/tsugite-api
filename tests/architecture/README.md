# プロジェクト全体のアーキテクチャ規則

`task test:architecture` で以下の規則と検査器自身の回帰テストを実行する。PRのCIでは `task test` が同じディレクトリを収集する。

| 対象 | 検査する規則 |
| --- | --- |
| バックエンド | DBとエージェントのジョブ受付を利用できる。画面、CDK、モデル推論の実装を直接インポートしない。公開カタログ操作のIDとルーターを維持する。 |
| データベース | ORM、接続、マイグレーションをHTTP・画面・CDKから独立させる。 |
| フロント | ブラウザー用コードがバックエンド、DB、CDK、エージェント、モデルに直接依存しない。 |
| フロントの画面分割 | `pages/<画面名>/` がURLと `components/` の部品を結び付ける。画面間の参照、部品から画面への逆参照、ページ内の独自描画、共通処理への画面分岐、API層外のHTTP通信を検出する。CSS・HTML・SVGの先頭コメントとPythonの公開関数の日本語説明も検査する。 |
| インフラ | CDKの起動スクリプトと構成定義が、配備するアプリやモデルのモジュールを読み込まない。リソース設定値・タグ・費用・スナップショットは各CDK単体テストで確認する。 |
| エージェント | 実装は `packages/agent/src/` に置く。バックエンドとDBを利用できる。検索処理からはガイド本文とガイド検索を再利用できる。推論実装と画面描画を直接インポートしない。 |
| モデル | 実装は `packages/model/src/` に置く。推論コードをAPI、ジョブ処理、画面、DB、CDKから独立させる。モデル取得元をコミットで固定し、重みにSHA-256を持たせる。 |
| 開発ツール・テスト | 実行用コードから開発ツールやテストをインポートしない。開発ツールは各層の実装を参照でき、テスト用コードの読み込みを検出する。各層の単体テスト、E2E、このディレクトリのテストに、条件と期待結果を日本語1行で書く。 |
| CIの検証範囲 | 各パッケージの依存宣言と実装のimportから、変更時に利用側のテストも選ばれることを確認する。文書、CSS、単体テスト、モデル定義、AWS Emulatorの差分で、必要なスイートとCDK合成の有無を検査する。 |
| 文書 | ルート、各パッケージ、要件、生成設計書などのMarkdownに、日本語を含む表題を書く。要件は索引生成器と同じ規則でファイル名・要件文・4節・共通語彙を検査する。API・DBの和名は定義元のコメントから取得し、設計情報の外部辞書や正規表現でのコード解析を検出する。 |

Pythonの依存規則は `core/dependencies.py` に定義する。新しいパッケージを加えたら所属層と許可する依存を定義し、`test_rule_checks.py` に適合例と違反例を追加する。エラーには対象ファイル、行番号、依存先が表示される。

規則を変えたときは `task test:mutation -- --layer architecture` をローカルで実行する。検査器の条件を一時コピーで変更し、その変更を回帰テストで検出できるか確認する。

共通規約は `core/`、パッケージ固有の規約は同じ階層の `backend/`、`frontend/`、`database/`、`agent/`、`model/`、`sample_api/`、`infra/`、`tools/` に置く。パッケージを追加するときは `packages/<名前>/tests/` と `tests/architecture/<名前>/` の両方にpytestのテスト関数を用意する。Pythonの実装（`.py`）と型定義（`.pyi`）の先頭には、ファイルの役割を日本語のモジュールdocstring（`"""説明"""`）で一度だけ書く。

`task test:unit-coverage` は、各パッケージ自身の単体テストで通過した実行文の割合（C0）と分岐の割合（C1）を表示する。合格条件はC0が90%以上、C1が85%以上。E2Eや別パッケージのテスト結果はこの判定に加算しない。CIは同じ判定を、パッケージ別に保存したpytest-covの計測結果に適用する。
