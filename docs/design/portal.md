# 継手API ポータルの画面仕様

Amazon DataZoneのデータポータルで使う「提供プロジェクトのインベントリ」「公開カタログ」「プロジェクト単位のサブスクリプション」を、APIの公開と利用に対応づける。認可の単位はAPI・利用プロジェクト・環境の組み合わせとする。

|利用者の仕事|入口と操作|画面で確かめること|
|---|---|---|
|提供者が出品する|提供するAPI → APIを登録 → 下書きを保存 → 詳細で公開|下書きは提供者だけが見られる。接続確認に成功するとカタログに載る|
|利用者が選ぶ|APIカタログ → キーワード・環境で検索 → 詳細|用途・提供元・対応環境・OpenAPIの操作を、申請前に確認できる|
|利用を申請する|詳細でプロジェクト・環境・目的を指定 → 自分の申請|申請中は実行できない。申請者は取り下げられる|
|提供者が判断する|届いた申請 → 理由を記入して承認または却下|申請者が理由を読める。却下・取下げ後は再申請できる。古い判断の再送は拒否する|
|利用者が実行する|自分の申請 → APIを開く → 承認環境で実行|応答コード・本文・照合用IDを表示する。別環境、別プロジェクト、却下、権限取消では転送しない|
|掲載と権限を終了する|提供するAPIで掲載を取り下げる。届いた申請から権限を取り消す|掲載終了で新規申請を止め、既存の権限は取消まで有効とする|
|監査担当が追跡する|監査履歴 → 操作またはリクエストIDで絞る|提供元、主体、プロジェクト、環境、判断理由、実行の開始・終了・拒否を照合できる。運用ログにも同じIDを記録する|

## レイアウトと操作

- 背景と同系色の共通ヘッダーに製品名と利用者の所属を表示する。左ナビゲーションで探す・利用する・提供する・監査する仕事を分ける。現在地をパンくずと太字とグレーの選択背景で示す。
- 公開一覧ではAPI名、用途、提供元、環境を同じ位置にそろえる。検索条件は一覧の直前に置き、総件数と表示範囲を明示する。1ページ12件とし、検索し直したら先頭に戻る。
- 主要操作は背景と明暗を反転させ、リンクには下線、補助ボタンにはグレーの輪郭、利用可能は緑、承認待ちは黄系、却下・拒否は赤とし、状態名を必ず併記する。入力にラベル、操作にフォーカス枠を付ける。
- 狭い画面ではメニューをボタンで開閉し、カードを1列に並べる。長い識別子や応答を折り返す。390px幅でページ全体の横スクロールが生じないことを確認する。
- レビューでは公開済みデータを使い、検索、ページ境界、空の検索結果、判断理由、取消後の応答を確認する。自動検証と撮影した実画面を対応づける。

参考資料：[Amazon DataZoneの公開](https://docs.aws.amazon.com/datazone/latest/userguide/publishing-data.html) ／ [サブスクリプション申請](https://docs.aws.amazon.com/datazone/latest/userguide/subscribe-to-data-assets-managed-by-datazone.html)

## 役割と利用状況

|役割|ホームからできる操作|利用状況の範囲|
|---|---|---|
|管理者（Cognitoの admin グループ）|ユーザーの追加・削除、全体または所属先への通知、利用上限の設定|全プロジェクト|
|提供者|自チームのAPIの登録・公開・変更・掲載停止・削除、申請の判断、申請元への通知と上限設定|提供APIと自身の利用プロジェクト|
|利用者|検索・利用申請・呼び出し、通知の確認と既読への変更|所属する利用プロジェクト|
|監査担当|業務監査とアクセスログの照合、メトリクスの閲覧|全プロジェクト|

掲載停止は新規の申請を止める。名称・説明の編集は既存契約を引き継ぐ。OpenAPI・接続先・ベースパスの変更時は下書きに戻し、承認待ちを終了し、利用権を取り消す。削除時も利用権を終了し、監査記録を保持する。ユーザーを削除すると既発行の個人トークンによる利用も停止する。

グラフはポータルのアクセス記録をUTCで集計する。期間、間隔、API、環境、プロジェクト、HTTPステータスと表示指標を選べる。棒を選ぶと、その時間帯のログに移動する。アクセスログと業務監査はリクエストIDで照合し、絞り込んだ記録をJSON Linesで保存できる。

上限はAPI・利用プロジェクト・環境の組み合わせごとに、UTCの固定区間で数える。転送前に1件を確保し、上限に達した時点でプロジェクトへ1回通知する。停止設定では次の呼び出しからHTTP 429を返し、期間が変わると自動で再開する。設定変更時は件数をリセットする。ベルの未読は個人別に管理する。

## 部署・プロジェクトと利用権

管理者は「組織・プロジェクト」で部署の表示名と親を設定する。部・課・係などの区分と階層数は固定しない。ユーザーは上位部署に直接所属でき、部署・プロジェクトを兼務できる。各所属に役職名とリーダー権限を付ける。プロジェクトには任意で管轄部署を指定する。

申請対象はプロジェクト全員か本人を選ぶ。チームに所属していない人も「個人ワークスペース」から本人として申請できる。提供者は詳細画面で公開する部署とプロジェクトを選ぶ。部署には子孫部署を含む。検索・詳細表示・申請・呼び出しで公開条件を確認する。

申請者の部署または役職が提供者の指定条件と一致すると、その申請は自動承認される。その他の申請は提供者、または申請者が所属する部署について提供者が指定したリーダーが承認・却下できる。委任先は自分自身の申請を判断できない。プロジェクト単位の承認は同じプロジェクト全体に適用される。本人単位の承認はプロジェクトの共有キーでは利用できない。

## APIキーと実行

「APIキー」からプロジェクトとキーの種類を選ぶ。発行本数にアプリ独自の固定上限はない。秘密値を表示するのは発行時の1回だけで、DBにはハッシュ値を保存する。発行後の一覧には名前・範囲・状態を表示する。取り消すと同じキーでの次の実行を拒否する。

|キー|外部アプリからの指定|呼び出せる範囲|
|---|---|---|
|共有|Authorization の Bearer に共有キーを指定|そのプロジェクトに承認された環境・API|
|本人限定|Authorization の Bearer に本人のアクセストークン、X-API-Key に本人限定キーを指定|対象プロジェクトで本人またはプロジェクトに承認された環境・API|

「すべてのAPI」を選んだキーにも公開条件・承認・停止状態が適用される。「指定したAPI」ではその共通範囲をさらに限定する。API詳細の「API Docs」ではOpenAPIの操作、引数、本文、応答仕様を確認し、対象キーを選んで実行できる。ログイン済みのブラウザーは選んだキーの識別子を送る。サーバーが本人性・所属・スコープ・失効状態を照合する。

共有キーだけで送った呼び出しは、プロジェクトの機械利用として管轄部署に計上する。ログイン中の個人による呼び出しは、その時点の所属部署・祖先部署にも記録する。同じ親部署で兼務する場合は1回として数える。部署停止は配下の部署・管轄プロジェクトに及ぶ。利用停止中も管理者・担当リーダーは状態を確認して再開できる。過去の呼び出しには実行時の組織情報を使い、機能追加前のログに部署を推定して付与することはしない。

## ハイブリッド検索

キーワード一致と日英の業務概念・OpenAPIタグ説明による意味の近さを別々に順位付けし、両方の順位を統合する。たとえば「両替」から為替APIを探せる。数値化する対象は閲覧可能なAPIだけで、未公開の商品やタグは件数・順位に影響しない。意味検索の範囲は業務語彙と登録されたタグ説明に依存する。
