# **開発者**は、**変更提案**を取り込むとき、**配備**を自動実行できる

## 背景

**配備**（承認された変更をAWS環境に反映する処理）はコード検証と異なる権限を必要とする。

## なぜ必要か

レビュー中の変更が本番に反映されることを防ぎ、取り込み後のテスト重複も避けるため。

## 決めた方針

PRでCIとカバレッジを検証し、mainへの取り込み後にCDを実行する。GitHubのmain Environmentに指定したロールをOIDCで使用し、CDKの配備にDB移行を含める。

> 実装検証 test_merge_deploy_workflow test_deploy_migration_lambda test_run_packaged_migration_on_postgresql — 配備ワークフローの依存順とマイグレーションの実行結果を確認する。

カバレッジを検査した回は、Verifyの概要で行カバレッジ率とXMLを含むline-coverage成果物へのリンクを確認できる。

> 実装検証 test_merge_deploy_workflow test_deploy_migration_lambda test_run_packaged_migration_on_postgresql — 配備ワークフローの依存順とマイグレーションの実行結果を確認する。
