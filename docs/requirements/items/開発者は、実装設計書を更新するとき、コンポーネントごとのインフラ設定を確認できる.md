# **開発者**は、**実装設計書**を更新するとき、**コンポーネント**ごとのインフラ設定を確認できる

## 背景

**コンポーネント**（CDKでリソースの所属を表す論理構成単位）ごとに、配備するリソースと設定をレビューする。

## なぜ必要か

リソースの所属と、参照先や配列の各要素を含む設定値を照合するため。

## 決めた方針

CDKが合成したCloudFormationテンプレートを読み、所属ごとに論理ID・タイプの一覧と、設定項目・値の表を生成する。配備時に解決される値は参照式を表示する。

### 受入テスト

- 受入テスト `tools/tests/test_infrastructure_docs.py::test_component_parameter_sheet`
- 受入テスト `tools/tests/test_infrastructure_docs.py::test_missing_component_identifies_resource`

## 却下した方針

複数の設定をJSONのまま一つのセルにまとめると、個々の項目の値を比較しにくい。
