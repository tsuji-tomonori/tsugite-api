# **開発者**は、**変更提案**に新しい要件を含めるとき、**要件ファイル**から要件一覧と用語一覧を生成できる

## 背景

**要件ファイル**（主体・条件・可能な操作と判断の背景を一件ずつ記した文書）は機能変更の起点になる。

## なぜ必要か

新しい機能に対応する要件をレビューでき、用語や索引を二重に管理せずに済むようにするため。

## 決めた方針

要件文をファイル名に使い、背景・なぜ必要か・決めた方針・却下した方針を記載する。CIは本文中の用語定義を集約し、featブランチの変更提案には新規要件を少なくとも1件求める。

## 却下した方針

一覧用のマップを手で更新する方法や、既存要件の編集だけでfeatブランチの条件を満たす運用は採用しない。
