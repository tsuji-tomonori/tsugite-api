# **利用者**は、**利用申請**を提出したとき、**承認の進捗**を確認できる

## 背景

利用申請には、提供者のみが判断するもの、部署やプロジェクトの担当が順番に判断するもの、自動で承認されるものがある。

## なぜ必要か

申請者が次に誰の判断を待つのかを自分で確認し、問い合わせずに利用開始の見通しを立てるため。

## 決めた方針

「自分の申請」に申請ごとのステータスを表示する。段階が指定された申請は、申請時の順番と判断履歴から現在の段階番号と担当を示す。「承認経路」を開くと、各段階の担当・状態・判断者・理由を表で読める。終了した申請には承認待ちを表示しない。自動承認、商品共通の承認ルール、経路の記録がない旧申請はそれぞれ区別する。

> 実装検証 test_applicant_sees_request_progress — 表示のみ：同じ担当を含む経路の現在地と終了後の各段階を確認する。

## 却下した方針

現在の商品設定から過去の申請経路を組み立てると、実際の審査順と異なることがあるため採用しない。
