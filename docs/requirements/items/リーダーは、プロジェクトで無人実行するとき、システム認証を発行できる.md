# **リーダー**は、**プロジェクト**で無人実行するとき、**システム認証**を発行できる

## 背景

**システム認証**（人のログインを必要とせずシステムの識別子で実行する認証方式）は定期処理で使う。

## なぜ必要か

プロジェクトが管理するバッチを、人のログイン状態から独立して実行するため。

## 決めた方針

プロジェクトの管理権限を持つメンバーが発行する。クライアント資格は固定の失効日を持たず、呼び出しに使うトークンは短期とする。資格の更新・失効で旧資格による利用を止める。

> Quint exchange.exchangeTest — 利用者資格の有無とシークレット更新後の交換を照合する。
> 実装検証 test_issue_use_and_retire_credentials — シークレット交換と旧資格の失効応答を実際の発行手順で確認する。

シークレット更新後は旧シークレットでの交換と旧トークンでの実行を拒否する。新しいシークレットで有効な範囲のトークンを取得できる。

> Quint exchange.exchangeTest credentials.rotatedTest — 利用者資格の有無とシークレット更新後の交換を照合する。
> 実装検証 test_client_tokens_reach_https — シークレット交換と旧資格の失効応答を実際の発行手順で確認する。
