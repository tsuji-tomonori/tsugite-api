# **管理者**は、**部署**や**プロジェクト**を統合するとき、**所属**と利用設定を移管できる

## 背景

組織改編に伴い、公開中の商品や承認済みの契約を後継組織へ引き継ぐ。

## なぜ必要か

提供者の再出品や利用者の再申請を避けるため。

## 決めた方針

詳細の「移管・削除」で同じ種類の後継組織を選ぶ。子組織、所属、商品、承認経路、利用権と認証情報を引き継ぐ。プロジェクトの移管後も旧プロジェクトを含むURLで呼び出せる。自分自身や配下への移管、停止中の組織を含む移管、設定の重複は拒否する。
