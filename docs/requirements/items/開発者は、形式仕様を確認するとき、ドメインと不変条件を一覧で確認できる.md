# **開発者**は、**形式仕様**を確認するとき、**ドメイン**と**不変条件**を一覧で確認できる

## 背景

Quintで表した**ドメイン**（モデルが扱う業務上の範囲）と**不変条件**（モデルの初期状態から到達できるすべての状態で成立すべき条件）を、開発者が日本語で読みたい。

## なぜ必要か

PRをレビューするときに、どの業務をどこまで形式検証しているかを一覧で把握し、元の条件式を確認できるようにするため。

## 決めた方針

モジュールとTLCが検査する不変条件の直前に日本語のドキュメントコメントを書く。Quintが出力するJSONとソースマップから、ドメイン、モデルの対象、不変条件と定義へのリンクを生成する。Verifyは必須コメントの欠落とコミット済み文書との差分を検出し、文書とリンク先のQuint定義を成果物に保存する。

> 実装検証 test_verify_runs_models_and_replays — 開発工程：文書生成と差分の検査が毎回のVerifyで動き、一覧と定義元が成果物に含まれる設定を確認する。

### 受入テスト

## 却下した方針

識別子と和名の対応表を別ファイルに置く方式は、定義の変更時に二か所の更新が要るため採用しない。
