# **提供者**は、**アクセストークン**の期限を制限するとき、**有効期間**を短縮できる

## 背景

提供者、上位部署、所属部署、プロジェクトが異なる上限を定める場合がある。

## なぜ必要か

複数の管理主体が設けた制限を同時に守るため。

## 決めた方針

提供者はAPI単位、リーダーは担当部署・プロジェクト単位で上限を設定する。兼務・複数APIを含めて最短値を使い、短縮後は発行済みトークンにも次回呼び出しから適用する。本人のログイン資格の残り時間も超えない。

> Quint credentials.lifetimeTest — 実行時点の最短の上限に達した瞬間から拒否する。
> 実装検証 test_provider_shortens_token_lifetime test_nested_token_lifetime — 部署階層とログイン期限を実際のトークンに反映することを確認する。

## 却下した方針

後から設定した長い上限で短い上限を上書きする方法は採用しない。
