# **提供者**は、**下書き**の接続を確認したとき、**商品**を公開できる

## 背景

**商品**（接続先・利用条件・操作仕様をまとめたAPIの掲載単位）には複数の操作がある。

## なぜ必要か

利用者が接続可能なAPIを選び、申請前に用途と仕様を判断できるようにするため。

## 決めた方針

接続確認の成功後にカタログへ掲載する。OpenAPI 3.0／3.1のJSONは内部参照のみ、500 KB以内とし、名称・説明・全操作を取り込む。

> Quint products.editTest — 文言変更と構造変更の後の公開状態・付与済みの権利を照合する。
> 実装検証 test_user_flow test_failed_probe_keeps_draft test_cognito_browser test_registration_validation — 接続確認の失敗とOpenAPI形式・サイズの受入条件を実装で検証する。
