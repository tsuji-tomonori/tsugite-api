# **利用者**は、本人の**利用権**でアプリを動かすとき、**アプリ認証**を発行できる

## 背景

**アプリ認証**（アプリの資格とログインした利用者の資格を組み合わせる認証方式）では人とアプリを識別する。

## なぜ必要か

利用者に許された範囲でアプリが操作し、実行した本人をたどれるようにするため。

## 決めた方針

クライアントID・シークレットと利用者のCognitoアクセストークンで短期トークンを取得する。

> Quint exchange.exchangeTest — 利用者資格の有無とシークレット更新後の交換を照合する。
> 実装検証 test_credentials_console test_client_tokens_reach_https test_issue_use_and_retire_credentials — アプリが取得した資格情報で上流を呼べることを確認する。

### 受入テスト

- 受入テスト `tests/e2e/browser/test_credentials_console.py::test_credentials_console` / `credentials.png`
- 受入テスト `tests/e2e/aws/test_credential_tokens.py::test_client_tokens_reach_https`
- 受入テスト `packages/backend/tests/test_quint_grants.py::test_exchange_contract`
- 受入テスト `packages/backend/tests/test_required_credentials.py::test_issue_use_and_retire_credentials`

## 却下した方針

アプリの資格だけで利用者本人として実行する方法は採用しない。
