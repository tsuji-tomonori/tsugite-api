# **開発者**は、**変更提案**を検証するとき、変更の影響がある**パッケージ**を検査できる

## 背景

**パッケージ**（リポジトリ内で依存関係を宣言しコードを管理する単位）をまたぐ参照がある。

## なぜ必要か

利用側の回帰を検出し、無関係なテストの実行を省くため。

## 決めた方針

Verifyは変更パスと依存する利用側に応じて対象テストと合成・エミュレーター検証を選ぶ。要件原本を変更した場合は全体を検証する。

> 実装検証 test_workspace_dependency_changes_verify_consumers test_verify_skips_unrelated_packages_even_without_coverage test_parallel_package_reports_are_combined_without_rerunning — 変更パスに応じたジョブ選択とカバレッジの集計を確認する。

エージェントと推論モデルの単体テストは、差分で選んだパッケージ単位で並列実行する。統合ジョブはそのJUnitとカバレッジを取り込む。
