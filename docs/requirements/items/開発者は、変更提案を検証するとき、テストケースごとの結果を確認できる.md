# **開発者**は、**変更提案**を検証するとき、**テストケース**ごとの結果を確認できる

## 背景

**変更提案**（ブランチの差分をレビューするプルリクエスト）に対し、どの条件を検証したかを知る必要がある。

## なぜ必要か

仕様のどこが壊れたかを、実装を読まずに特定できるようにするため。

## 決めた方針

**テストケース**（条件と期待結果を持つ検証単位）にE2Eを含めて簡潔な日本語の説明を付け、アーキテクチャテストで検査する。レポートには成否・実行時間・該当する画面を含める。

> 実装検証 test_report_image_viewer test_unexecuted_requirement_fails — JUnitと表示する画像・日本語の説明をレポートで確認する。

### 受入テスト

- 受入テスト `tests/e2e/browser/test_report_images.py::test_report_image_viewer` / `viewer.png`
- 受入テスト `packages/tools/tests/test_requirement_evidence.py::test_unexecuted_requirement_fails`

## 却下した方針

テスト関数名だけで業務上の期待結果を説明する運用は採用しない。

### 変更履歴

- 2026-11-25 開発ツールとアーキテクチャテストをパッケージ構成に合わせて移設したため、受入テストの参照先を更新した。

- 2026-11-26 方針ごとの検証先と観測する結果を明記した。
