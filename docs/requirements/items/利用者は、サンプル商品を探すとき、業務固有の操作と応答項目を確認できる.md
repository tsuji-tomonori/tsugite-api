# **利用者**は、サンプル**商品**を探すとき、**業務固有の操作**と応答項目を確認できる

## 背景

**業務固有の操作**（一つの商品の用途に対応し、他のサンプル商品とHTTPメソッドとパスの組み合わせが重複しない操作）を掲載する。同じ在庫照会仕様を複数の名前で掲載すると、カタログ検索がどの商品の業務に一致したか検証できない。

## なぜ必要か

例えば、倉庫の在庫数を調べる問い合わせと、返品後の再販価格を調べる問い合わせで、それぞれの業務に合う商品を判断するため。

## 決めた方針

検証用の各商品には実装から生成したOpenAPIを登録する。各商品は独自の業務操作を5件持ち、明細の応答項目の組み合わせも商品ごとに異なる。稼働確認は共通の `GET /health` で行える。既存商品を固有スキーマに更新した場合は構造変更として掲載を止め、既存の利用権と申請を終了する。

> Quint products.editTest — 商品固有のOpenAPIへの構造変更で掲載と承認済み利用権が終了することを検証する。
> 実装検証 test_catalog_business_operations_are_distinct test_generated_product_contracts test_each_product_operation_through_lambda — API契約を実装・公開仕様・Lambda応答で照合する。

## 却下した方針

商品名だけを変更して同じ業務操作とレスポンスを掲載する方式は、商品を識別する検証に使えないため採用しない。
