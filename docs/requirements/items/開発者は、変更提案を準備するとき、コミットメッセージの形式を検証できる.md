# **開発者**は、**変更提案**を準備するとき、**コミットメッセージ**の形式を検証できる

## 背景

**コミットメッセージ**（変更の種類と要点を記録するGit履歴の説明）は、変更を後から探す手がかりになる。

## なぜ必要か

履歴に同じ形式で変更の目的を残すため。

## 決めた方針

Conventional Commits形式のテンプレートを用意し、コミット時のフックで形式に合わないメッセージを止める。

### 受入テスト

- 受入テスト `packages/tools/tests/test_delivery_contracts.py::test_commit_message_hook`

## 却下した方針

テンプレートの案内だけに依存する運用は採用しない。
