# **開発者**は、判定モデルを**配備**するとき、重みを専用**レイヤー**で更新できる

## 背景

チャットで日本語を判定する関数は、推論用の重みとトークナイザーを使う。

## なぜ必要か

初回推論でのダウンロードをなくし、重みと推論ライブラリを個別に更新できるようにするため。

## 決めた方針

固定した重みとトークナイザーのハッシュをビルド時に照合し、uvで管理する依存と別のレイヤーに格納する。判定関数は起動後にローカルのファイルから推論する。配備前に関数本体と全レイヤーの展開後サイズを合算し、上限に達する配布物はビルドを失敗させる。

> 実装検証 test_model_layer_changes_are_isolated test_model_imports_from_deployment_packages test_model_package_limit_includes_all_uncompressed_layers test_decision_worker_loads_weights_and_tokenizer_from_layer test_generation_worker_reuses_downloaded_versioned_weights test_decision_layer_rejects_each_damaged_input — 重み・依存・ZIPの合算サイズは生成した配布物で確認する。

## 却下した方針

検索語生成と回答生成のモデルはそれぞれ単体で上限を超えるため、S3から実行環境ごとに初回だけ取得する。

### 変更履歴

- 2026-11-25 判定モデルが依存を含めても容量内に収まることを確認し、初回推論時のS3取得を省く配備方法を追加した。
- 2026-11-25 開発ツールの移設に合わせて参照先を更新し、判定資材のハッシュ照合とローカル読み込み、生成用の重みの再利用を受入条件に加えた。

- 2026-11-26 方針ごとの検証先と観測する結果を明記した。
