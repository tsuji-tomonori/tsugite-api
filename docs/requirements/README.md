# 目的

社内のAPIを一か所で探し、使う目的を伝えて申請し、承認されたら呼び出せるようにする。

# 要件

- 提供チームは、OpenAPIと接続先を選んでAPIを登録し、公開や掲載の取り下げができる。
- 利用者はAPIの用途・仕様を検索し、プロジェクトと環境を指定して利用を申請できる。
- 提供チームは申請を承認・却下し、付与した権限を取り消せる。
- 人とシステムを識別し、承認済みのプロジェクトだけが対象環境のAPIを呼び出せる。
- 掲載を取り下げると新規申請を止める。権限を取り消すと以後の呼び出しを拒否する。
- 公開、申請、判断、呼び出しの記録から、誰がいつどのAPIを利用したかをたどれる。

- 管理者はユーザーの追加・削除と所属の指定ができる。提供者は掲載内容を変更し、APIを削除できる。
- 管理者・提供者・利用者はホームで自分の範囲の利用状況を確認できる。提供者や管理者からのお知らせはベルで読む。
- 時間帯・API・プロジェクト・環境・応答コード別に利用状況を表示し、アクセスログと業務監査をダウンロードできる。
- 管理者と提供者は利用件数のしきい値を設定し、到達時に通知するか、通知に加えて次の期間まで利用を停止できる。
- 管理者は名称と深さを自由に決めて部署を階層化し、ユーザーの兼務、役職、リーダー、プロジェクトの所属を設定できる。
- 申請の対象はプロジェクト全員または本人とする。提供者は公開範囲、部署・役職による自動承認、部署リーダーへの判断の委任を設定できる。
- 利用者は公開範囲内を語句と意味で検索し、プロジェクトごとに複数の共有キー・本人限定キーを発行できる。対象は承認済みAPI全体または指定したAPIに限る。
- API Docsからキーを選択して呼び出せる。リーダーは担当部署・プロジェクトの所属・利用状況を確認し、利用を停止・再開できる。
